# UI: the local API and the event storming editor

status: draft · layer: cross-cutting (`08-store.md`, `24-eventstorming.md`) · schema: none

The first human-facing surface. `persimmon ui` serves a JSON API over the Store and the static
tools under `tools/`; the event storming editor is the first tool. The API is the first slice of
server mode (`08-store.md`): the same routes, without https and tokens.

```text
persimmon ui ──▶ src/server: http://127.0.0.1:4747
                  /api/...            JSON over the Engine: kinds, artifacts, one revision, create a revision
                  /tools/<name>/      static build of tools/<name>/ from dist/tools/<name>/
browser ──▶ /tools/eventstorming/?ns=default&id=<id>&rev=<n> ──▶ GET revision ──▶ edit ──▶ POST ──▶ revision n+1
```

## Verb

`persimmon ui [--port <n>]`

| Step | Rule |
|---|---|
| bind | `127.0.0.1` only, no option to widen it, default port 4747; no auth in local mode, the process owner is the local Actor (`08-store.md`) |
| origin | a request whose `Host` is not `127.0.0.1:<port>` or `localhost:<port>` is 403: a web page can reach loopback through a rebound DNS name; a `POST` without `content-type: application/json` is 415: a cross-site no-cors POST cannot send it, and a JSON one needs a preflight no page passes |
| drain | after every create the engine drains once, serialized, after the response: a publish may fire a Trigger, and nothing else drains while `ui` runs |
| engine | opened as the CLI opens it; the server holds no engine logic and reaches the Store through the Engine and the `create` path only |
| static | `dist/tools/<name>/`, `index.html` for the tool root and any path without a file extension; `/` redirects to `/tools/eventstorming/` |
| lock | the engine is opened listening, as `persimmon create` needs (a publish may fire a Trigger whose run calls an Adapter), so `persimmon ui` holds the project lock while it runs; another verb in the same project refuses to start until it stops |
| stop | SIGINT |

## API

`<kindName>` is a KindDefinition `metadata.name` (`eventstormings.sdd.persimmon.ai`), so a path
needs no apiVersion. Errors `{error: {code, message}}`: 400 bad input, 404 unknown, 409
conflict, 500.

| Route | Answer |
|---|---|
| `GET /api/kinds` | `[{name, apiVersion, kind, plural}]`, revisioned kinds only |
| `GET /api/artifacts?kind=<kindName>&namespace=<ns>` | `[{apiVersion, kind, namespace, id, revision}]`, one per id with its latest revision; `namespace` defaults to `defaultNamespace` |
| `GET /api/artifacts/<ns>/<kindName>/<id>` | `{apiVersion, kind, namespace, id, revisions: [n]}` ascending |
| `GET /api/artifacts/<ns>/<kindName>/<id>/<revision \| latest>` | the stored Resource: `apiVersion, kind, metadata, spec {identity, content, provenance}, status` |
| `GET /api/artifacts/<ns>/<kindName>/<id>/<revision \| latest>/<name>` | the bytes of that representation (`18-artifact.md`), by name or by `<name>.<ext>` as a sibling page links it; `content-type` its `mediaType` (`charset=utf-8` on `text/*`), with `Content-Security-Policy: sandbox`, `X-Content-Type-Options: nosniff` and `Cross-Origin-Resource-Policy: same-origin`; 404 when the revision names no such representation, 500 when its blob is missing. No script runs in a served page, and a PDF under the sandbox is unverified in a browser |
| `POST /api/artifacts/<ns>/<kindName>/<id>` `{content, base?}` | the next revision through the `persimmon create` path, `createRevision` in `cli/create`, which retries once with the number the engine names when the reserve counter ran past an abandoned revision: schema validation, engine-stamped provenance; 201 with the RevisionRef; 400 with the engine's message on a schema violation; 409 `conflict` when `base`, the revision the client edited, is not the latest, so two tabs never fork a lineage silently; 413 over 16 MiB |

Read and create only: a revision is immutable, so there is no update or delete.

## Editor

`tools/eventstorming/`: Vite + React + React Flow, the old tool's editor ported; built into
`dist/tools/eventstorming/` by `npm run build`.

| Kept from the tool | Dropped, and what replaces it |
|---|---|
| editor shell, structured board, discovery canvas, custom nodes and edges, property panel, filters, context map, walkthrough, health panel, layout, store | projects and IndexedDB: the Store; autosave: Save is a revision; snapshots and compare: revisions; the Zod schema: the kind schema at the API; `health.ts`: the grammar module's `check` |

| Action | Behaviour |
|---|---|
| open | `?ns=&id=&rev=`; `rev` defaults to `latest`; without `id`, a picker over `GET /api/artifacts` and "new model" |
| save | `POST` the content with `base`, the revision edited; navigate to the new revision; a 409 asks to reload; the status line shows ns, id, rev and unsaved changes; the tab warns before closing with unsaved changes |
| older revision | opened read-only: no canvas edits, Save disabled; "edit as new revision" lifts it and the save goes to latest + 1 with `base` the latest, the status line says which revision it forks from |
| import file | an old `.eventstorming.json` or a YAML Resource file; `spec.content` taken, `meta.createdAt` stripped; only `version: "4.0"` or `"4.1"` with a `meta` object, anything else named and refused |
| open failure | an empty editable board only for `latest` of an id that does not exist; any other failure shows the message and opens nothing, so a save never overwrites an id by mistake; the picker refuses a new id that exists |
| export | a YAML Resource file for the next revision, `metadata.name: <id>.r<n+1>` and `spec.identity`, so `persimmon create` of it stores it |
| health | `check(content)` live, the grammar's findings, the same the Validator reports |

## Rules

| Rule | Enforcer |
|---|---|
| the server binds loopback only in local mode; Host and content type checks keep other origins out | `persimmon ui`, `src/server/api.ts` |
| the API creates revisions through the same path as `persimmon create`; no second write path | `src/server` imports `cli/create` |
| a tool's model code has no DOM dependency and is tested without one; the UI itself has no unit tests in v1 | `test/tools/`, `tools/*/src/**/*.test.ts` |
| tool dependencies live in the root `package.json`; one lockfile | convention |
| the root `tsc` build never compiles a tool; each tool has its own `tsconfig.json` and Vite builds it | `tsconfig.json` include |

## Decisions

- The local API is server mode's first slice, not a throwaway: the routes are what a remote
  client needs, local mode leaves out https and tokens. `src/server/` is created for it.
- Vite over Next: a static single-page editor needs no routing or server rendering, and the
  engine's build stays `tsc` plus one Vite call.
- React Flow kept: the old tool's layout and canvas code depends on it and is the bulk of the
  port; replacing it would be a rewrite, not a port.
- Read and create only on the API: a revision is immutable (`05-revisioned-kind.md`); edit is a
  new revision, and nothing in the UI may need delete.
- The editor trusts the API's 400 for the schema and runs the grammar itself for findings: one
  schema, in the pack; one grammar, in `tools/eventstorming/grammar`.
- Dependencies, each a decision (`CLAUDE.md`): `react` and `react-dom` because the port is React
  code; `@xyflow/react` because the canvas, layout and edge code are written against it, a replacement
  would be a rewrite; `zustand` because the store is; `vite` and `@vitejs/plugin-react` over Next.js, a
  static page with no routing or server rendering; `tailwindcss` with `@tailwindcss/vite` because every
  ported component is Tailwind classes end to end and converting them would be a redesign; `lucide-react`
  for the forty icons the components already name. Dropped: `zod` (the schema is the kind's), `nanoid`
  (one line of `crypto.randomUUID`), `next`. Versions pinned to what the old tool's lockfile resolved.
  Found in implementation.
- The old `migrate.ts` is not ported: for v4.0 input it is the identity, so only v4.0 files import;
  older formats are migrated once with the old tool. Found in implementation.
- The published package ships `tools/eventstorming/grammar` beside `dist`, `adapters` and `packs`:
  the evaluator Adapter imports it at runtime and the built editor is under `dist/tools`. Found in
  audit.
- No auth on loopback is not no checks: a browser carries any page's requests to 127.0.0.1, so the
  Host header and a JSON content type on POST stand in for an origin policy until server mode's
  tokens. Found in audit.
- A representation is served as the bytes the agent published, under `Content-Security-Policy:
  sandbox`. An agent's HTML is untrusted and the route puts it on the API's origin, where a
  script in it could read every artifact and `POST` revisions with the viewer's standing; the
  sandbox with no token runs no script at all, submits no form, opens no popup and gives the
  page an opaque origin, and the page still renders with its inline CSS and images. A clickable
  mockup does not click; `allow-scripts` can come when one needs it, the origin stays opaque.
  Rewriting the HTML or serving it from another port was more code for less: the bytes stay
  what the digest pins. `nosniff` keeps a `text/plain` blob from being read as HTML;
  `Cross-Origin-Resource-Policy: same-origin` keeps any site the user visits from reading a
  `.js` or `.css` representation through `<script src>` on 127.0.0.1, which the Host check
  alone lets through. Found in design review; the last two found in audit.
- Projects, autosave, snapshots and compare are not ported: the Store is the project, a revision
  is a snapshot, two revisions are a compare. Found in design review.
